# 音楽再生の UI 設計

状態: 作成済み（2026-11-08）。未確認のことは末尾の「未確認のこと」を参照。

## 意図

音楽再生アプリの画面を、LVGL で作る。目的は、キーだけで操作できる、見やすい再生画面を持つこと。
将来は複数のアプリを切り替える（README 参照）が、今回は音楽再生だけを対象にする。

LVGL は、試作ブランチ `feat/lvgl-spike` で、次の 3 点を確認済み。

- 画面表示: LVGL が RAM 上に描き、M5GFX（`M5.Display`）で転送する。
- キー操作: キー入力デバイスを登録すると、リストの選択とスクロールが動く。
- 日本語: LVGL 標準の `Source Han Sans SC 16 CJK`（約 1338 文字）で表示できる。含まれない漢字（例: 龍、鬱蒼）は □ になる。

## 目標・非目標・やってはいけないこと

目標
- 一覧と再生中の 2 画面を、LVGL で作る（下記の画面設計）。
- 一時停止、次の曲、前の曲、1 曲リピートを追加する。
- 再生中に、音に合わせて動くイコライザーを表示する。
- 電池の残量（おおよそ）と音量を、常に表示する。

非目標（今回やらない）
- 複数アプリの切り替え
- OTA（WiFi 書き込み）
- 日本語フォントの拡張（足りない漢字の対応）。必要になったら別に検討する。

やってはいけないこと
- 画面の描画が、音の再生を途切れさせる。
- LVGL を、LVGL のタスク以外から触る（スレッドセーフではないため）。

## 制約

- 画面は 240x135（RGB565）。PSRAM はなく、内蔵 RAM は 512KB。
- フラッシュは 8MB、アプリ用パーティションは 3MB（`partitions.csv`）。
- `CONFIG_FREERTOS_HZ=100`（1 tick = 10ms）。待ち時間は `msToTicks()` を使う（CLAUDE.md 参照）。
- LVGL 9.5.0。`lvgl_port` は M5 に依存させず、転送の関数 `FlushFn` とキー取得の関数 `PollKeyFn` を引数で受ける（試作のとおり）。M5GFX への依存は `pocket-deck.cpp` に置く。
- 日本語のファイル名は、標準の CJK フォント（約 1338 文字）で表示できる範囲に限る。

## 画面設計

画面は、上の細い帯（共通）と、その下の本体からなる。以下は寸法の目安で、色や細部は実装者が決める。

共通の帯（高さ約 14px、右寄せ）
- 音量: スピーカー（四角の組み合わせ）+ 太め（2px）の弧 3 つ。16 段階を、約 5 段階ごとに 1 本で表す。消音は、スピーカーを暗くして斜線を重ねる。
- 電池: 横長の枠と中身。中身の長さで残量を表す。
- 画面名は出さない。

一覧の画面
- 帯の下に、約 6 行（1 行 約 20px）のリスト。選択中の行を強調する。
- 項目が多いときは、スクロールする（現在の最大 7 件の制限は、なくなる）。

再生中の画面（上から）
1. 曲名
2. イコライザー（12 本程度の縦棒。高さの目安は約 54px）
3. 再生位置のバー
4. 再生状態（再生中 / 一時停止）、リピートの印、時間（`01:23 / 03:45`）

```
+------------------------------+
|                    (音量)(電池)|  帯
| 03_日本語の曲.wav              |
|  ▂ ▄ ▆ █ ▆ ▅ ▃ ▅ ▃ ▂ ▁ ▁      |  イコライザー
| ━━━━━━━━────────────────────  |  再生位置
| ▶ 再生中   🔁        01:23 / 03:45 |
+------------------------------+
```

## 操作

| 画面 | キー | 動作 |
|------|------|------|
| 一覧 | j / ↓、k / ↑ | 選択を移す |
| 一覧 | Enter | 選んだ曲を再生し、再生中の画面へ |
| 再生中 | Space | 一時停止 / 再開 |
| 再生中 | l / →、h / ← | 次の曲、前の曲 |
| 再生中 | r | 1 曲リピートの切り替え |
| 再生中 | Esc | 一覧に戻る（再生は止める） |
| 共通 | Fn + A / S / D | 音量を上げる / 下げる / 消音 |

## 進め方（Approaches）

検討した案
- A: 段階的に置き換える。土台 → 一覧 → 再生中の画面の順に、各段階でビルドと実機確認をする。古い `ui.cpp` は最後に消す。
- B: `ui.cpp` を一気に作り直す。手戻りは減るが、作業が大きく、途中の確認がしにくい。

採用: A（理由: 1 つずつ issue にでき、途中で動かなくなっても戻れる。試作の `lvgl_port` を土台にできる）。

LVGL を使わず、現在の `ui.cpp` を広げる案は、LVGL を使うという前提に合わないので外した。

### 段階（issue の分割案）

1. LVGL の土台と上の帯（音量。電池は仮の表示）。試作の `lvgl_port` を `main/ui/` に取り込む。
2. 一覧の画面（スクロール対応）。古い一覧の描画を置き換える。
3. 再生中の画面（曲名、再生状態、再生位置、時間）。`ui.cpp` の古い描画を削除する。
4. 一時停止、次の曲、前の曲、リピート（`player` の作り直しを含む）。
5. イコライザー。
6. 電池残量の実装。

## 実装者に任せること

- 色、フォントサイズ、余白、アニメーションの細部
- 一時停止の実現方法（案: 再生タスクを止めて、読み出し位置を覚え、再開時にそこから再開する）
- イコライザーの計算方法と本数（案: 再生タスクが、スピーカーに渡す前のデータを FFT し、帯域ごとのレベルを LVGL のタスクに渡す）
- 前の曲 / 次の曲 の順序の決め方（一覧の並びに従う、が自然）

## 未確認のこと（リスク）

- 電池: `M5.Power` は、Cardputer-Adv では GPIO10 の ADC（分圧比 2.0）で電圧を測る設定。残量は粗い値になり、充電中の表示は取れない可能性がある。実機で確認が必要。
- イコライザー: FFT の CPU 負荷と、音が途切れないかは未確認。映像が音より少し先に動くずれが出る。
- 画面の描画負荷: 弧などの描画が小さく滑らかに見えるか（アンチエイリアスの見え方）は、実機で確認が必要。
- 日本語: 標準のフォントに含まれない漢字は □ になる。

## 確認済みの判断

- 電池の残量は、おおよその値でよい。
- イコライザーの本数は、12 本とする。
- 一覧の行数は、6 行とする。
- リピートは 1 曲のみとし、全曲リピートやシャッフルは入れない（ひとまず）。
