# タスクとタスクの間の連絡

値の出どころは `main/task_config.hpp`。値を変えるときはそこだけを直し、この文書も合わせる。

## 方針

- 優先度: 音の経路（スピーカー・再生用）> 描画（LVGL）・キーボード > イコライザーの計算。
- コア: 音の経路（スピーカー・再生用・イコライザーの計算）はコア 0、描画（LVGL）はコア 1。指定しないと描画も音もコア 0 に集まり、再生中は描画が間に合わない（実機で計測、#57）。
- FreeRTOS の tick は `CONFIG_FREERTOS_HZ=100`（1 tick = 10ms）。

## タスクの一覧

| タスク | 名前 | 優先度 | コア | スタック | 作る所 |
|--------|------|--------|------|----------|--------|
| LVGL | `lvgl` | 5 | 1 | 8192 | `lvgl_port::start()`（起動時に 1 回） |
| キーボード | `keyboard` | 5 | 指定なし | 4096 | `keyboard::begin()`（起動時に 1 回） |
| 再生用 | `player` | 6 | 0 | 4096 | `player::start()` / `resume()`（再生のたびに作り、終わると自分で削除） |
| イコライザーの計算 | `spectrum` | 1 | 0 | 3072 | `spectrum::begin()`（起動時に 1 回） |
| スピーカー | （M5Unified が作る） | 6 | 0 | 既定のまま | `speaker::begin()` が設定を渡して `M5.Speaker.begin()` |

「指定なし」は `CORE_ANY`（`tskNO_AFFINITY`）で、OS がコアを選ぶ。

## 理由

- **LVGL（5 / コア 1 / 8192）**: 描画のために、音の経路とは別のコア 1 に置く。スタックの 8KB は、他のタスクより大きい（`task_config.hpp` に理由の記述はない）。
- **キーボード（5 / 指定なし / 4096）**: I2C の読み書きとキューへの送信しかしないので、4KB で足りる。優先度は LVGL と同じ。割り込み（ISR）の通知で起きたときだけ動くので、CPU はほとんど使わない。
- **再生用（6 / コア 0 / 4096）**: ファイルの読み出しと `playRaw()` の呼び出しだけなので、4KB で足りる。
  - 優先度をスピーカーと同じ 6 にしているのは、再開後は SD の読み出しが遅く、5 だと LVGL の描画に CPU を取られて音のキューが空になるため。
  - SD の読み出しは CPU を使い続けるので、描画と同じコアに置くと描画が間に合わない。
- **イコライザーの計算（1 / コア 0 / 3072）**: 1 回に約 6ms（最大約 12ms、実機で計測）かかるので、優先度を音の経路より低い 1 にして音を優先する。計算が間に合わなければ、そのチャンクは捨てる（棒の動きが粗くなるだけ）。
- **スピーカー（6 / コア 0）**: LVGL・キーボードより高くする。既定の 2 では、イコライザーの描画が忙しいときに CPU を取れず、音が途切れた（実機で確認）。スタックは M5Unified の既定のままなので、`task_config.hpp` では 0 としている。

## LVGL のタスクの中で動くもの

LVGL のタスク（`lvglTask`）は `lv_timer_handler()` を周期的に呼ぶ。次の処理はすべてこのタスクの中で動く。`playback` に排他制御がないのは、このためである。

| 処理 | 周期 | 内容 |
|------|------|------|
| キー入力デバイスの読み出し（`keypadReadCb`） | 呼ばれるたび | `ui.cpp` の `pollKey()` → `input::poll()`。音量のキーもここで処理する |
| `now_playing::poll` | 100ms | `playback::update()` で終了通知を処理し、表示を更新する |
| `eq_view::poll` | 40ms | `spectrum::levels()` を読んで棒を更新する |
| `volume_icon::poll` | 50ms | `volume::level()` / `muted()` を読んで、変わっていたら描き直す |
| `battery_icon::poll` | 5000ms | 電池の残量を読んで表示する |

`lv_timer_handler()` の待ち時間は、返された値を 5〜50ms に収めて使う。

## タスクの間をつなぐもの

| 名前 | 種類 | 送る側 → 受ける側 | 内容 |
|------|------|-------------------|------|
| TCA8418 の INT | GPIO の割り込み + タスク通知 | `intHandler`（ISR）→ `keyboard` タスク | キーが押された。I2C は ISR から呼べないので通知だけ送る |
| キーのキュー（`s_queue`、長さ 16） | キュー | `keyboard` タスク → LVGL のタスク | `KeyEvent`（押された瞬間だけ）。満杯なら新しいイベントを捨てる |
| 終了通知のキュー（`eventQ`、長さ 4） | キュー | `player` タスク → LVGL のタスク | `EndReason`（`Finished` / `Stopped` / `Failed`）。1 回の再生につき 1 件 |
| 窓の通知（`s_task`） | タスク通知 | `player` タスク → `spectrum` タスク | `submit()` が窓をコピーして `xTaskNotifyGive()`。計算中なら、そのチャンクは捨てる |
| レベル（`s_level`） | 共有変数（`volatile`） | `spectrum` タスク → LVGL のタスク | 12 帯域のレベル（0〜100）。`levels()` で読む |
| 保存タイマー（`vol_save`、1000ms の one-shot） | ソフトウェアタイマー | `volume::markChanged()` → タイマータスク | 最後の音量の変更から 1 秒後に `save()` で NVS に書く |
| `running` / `stopReq` / `playedBytes` | 共有変数（`volatile`） | `player` の呼び出し側 ⇄ `player` タスク | 動作中の印、停止の要求、再生した量（再生位置の目安） |

### 再生用のタスクの終わり方

`playTask` は、どの経路で終わっても最後に終了通知を 1 件だけ送る。送ってから `running` を下ろす。これで `stop()` から戻った時点で、通知がキューに入っていることが保証される。`playback` は自分で止めたとき（曲の切り替え・一時停止・停止）に溜まった通知を `drainEvents()` で捨て、終了と取り違えないようにする。
